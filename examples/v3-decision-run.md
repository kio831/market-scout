# 示例：V3 完整决策链（v3.0.0）— 机会评分 → 决策 → MVP → 行动计划

> ⚠️ 本示例为**演示流程用**：人物、价格、评论为示意，仅用于展示 V3 的评分可复算、决策可解释、MVP 与行动计划如何衔接。
> 真实运行必须 Search First（三类搜索）取得实时证据，并按 Evidence/Inference/Unknown 三态如实标注；搜索通道不可用时按 v3-evidence.md §6 降级并声明。
> 本示例对应自测 Case 4：一个"明显值得做"的简单方向，检查能否从分析一路进入 MVP Blueprint 与 Action Plan。

## 用户输入

"我身边很多小店主（餐饮、美甲、教培）想在小红书获客但不会写种草文案，找代运营一个月要好几千。我想用 AI 帮他们写，这个值不值得做？如果值得，第一版做什么？"

**模式判定**：要求"值不值得做 + 第一版做什么" → V3 决策层九步主流程，分配 **Opportunity ID：MS-104**。

## 1. Market Evidence 市场证据（三态）

| # | 结论 | 状态 | 来源（示意/待实时核实） |
|---|---|---|---|
| 1 | 小红书是本地小微商家重要的获客渠道 | Evidence | 平台公开数据（示意） |
| 2 | 大量小店主"不会写/写不出效果"的抱怨与求助 | Evidence | 商家社群/评论区多平台重复出现（示意，≥15 条） |
| 3 | 代运营公司收费 2000-5000 元/月，小店主嫌贵 | Evidence | 在售服务公开报价（示意，需实时核实） |
| 4 | 通用 AI 写出来"没行业味"，需大量人工改写 | Inference | 用户反馈归纳（示意） |
| 5 | 小店主愿意为"低价+懂行+成品交付"的文案服务月付 | Inference | 由 1-4 推导，本方案付费未验证（假设） |

证据充分度：**Partial**——付费信号为 Inference（有明确验证路径：样品→报价→收款）。

## 2. Pain Point 核心痛点

- 痛点：想获客但不会写种草文案；代运营太贵；通用 AI 不会用、没行业味。
- 不解决的损失：淡季客流少、获客全靠老带新，月损失以千元计（示意）。
- 现有方案与不满：自己硬写（费时低效）/ 代运营（贵）/ 通用 AI（无行业味）。

## 3. Competition 竞品与市场空缺

- 竞争格局：**分散小玩家**（大量个人代写/小代运营，无主导者）。
- 切入空间四问：① 真实需求 ✅（重复求助证据）；② 竞品解决不到位 ✅（贵、模板化）；③ 用户仍抱怨 ✅（嫌贵/嫌没行业味）；④ 可守切入点 ✅——**垂直品类 + 成品交付 + 低价包月**，对手要复制需先积累行业语料与案例。
- 结论：切入空间成立（Evidence/Inference），Competition 70 分。

|---|---|---|---|

## 5. Decision 机会决策

> **🟢 RECOMMENDED 值得继续做**｜机会评分 **78/100**｜需求 80｜变现 80｜Opportunity **MS-104**
> 一句话结论：垂直品类的小红书文案代做，付费市场已被代运营验证，切入空间成立，可低成本起步。

Why：
1. 痛点明显且重复出现，现有方案被公开抱怨（Evidence）。
2. 需求证据多、主动寻找强，付费市场已被代运营价格验证（Evidence）。
3. 竞品分散、存在"垂直品类+成品交付+低价包月"的可守切入点（Evidence/Inference）。
4. MVP 开发难度极低：L1 人工+AI 即可，本周可交付第一单（Inference）。
5. 付费路径明确：代运营 1/10 价格锚 + 小店主自付自决（Evidence/Inference）。

## 6. MVP Blueprint（9 字段，完整版）

| # | 字段 | 内容 |
|---|---|---|
| 1 | Product 产品定位 | 我帮本地小店主（餐饮/美甲/教培）在【小红书】用【包月成品文案】达成【稳定获客线索】，比代运营便宜一个数量级 |
| 2 | Target User 目标用户 | 1-2 家店的小店主/主理人，自兼运营，活跃于本地商家群与小红书（先在 1 个城市 1 个品类试点） |
| 3 | Core Problem | 想在小红书获客但不会写、没时间写、雇不起代运营（VALDATE 结论） |
| 4 | Core Value | 每月 8 条"能带来到店咨询"的成品种草图文（文案+选题+配图建议），省下每周 4-6 小时或每月数千元 |
| 5 | Must Have（≤3） | ① 每月 8 条垂直品类成品图文包；② 1 套活动/引流文案；③ 按门店风格微调（每项对应一个付费理由） |
| 6 | Nice to Have | 短视频脚本、周数据复盘、节日活动策划 |
| 7 | Do Not Build | 不做账号体系/后台/App/自动发布/多平台代运营/付费投流 |
| 8 | Build Difficulty | L1 人工+AI，现金成本≈0，首月单店 4-6 小时人工——【当前不需要开发】 |
| 9 | Recommended Stack | 无代码：通用大模型 + 品类提示词模板库 + 飞书表格排期 + 人工质检（理由：最快验证付费；最大缺点：依赖人工；替代：轻脚本半自动化） |

MVP 五项：做什么=一家店一个品类一个月成品图文包；不做什么=不开发任何工具；验证什么=是否愿为"成品结果"按月付钱；继续条件=2 周内 ≥3 家真实付款；放弃条件=接触 20 家无人付费。

最小验证实验：假设=小店主愿为成品文案月付；形式=Concierge+免费样品+首月预售；对象=本地 5 家最匹配小店；成功标准=≥3 家真实付款（99-199 元体验价）；失败转向=换品类→换报价→放弃。

## 7. Action Plan 行动计划（LOCAL_SERVICE，执行路径）

| Step | 目标 | 做什么 | 成功标准 | 失败转向 |
|---|---|---|---|---|
| 1 | 样品交付 | 给 3 家熟悉小店各做 1 条免费样品（前后对比） | 3 家都认可"能用" | 改进样品模板 |
| 2 | 报价收款 | 48 小时内报价 199 元首月，先收钱再交付 | ≥3 家真实付款 | 降体验价/换品类 |
| 3 | 第一单交付 | 交付 8 条成品 + 1 套活动文案 | 客户愿意转发/续费 | 复盘不满点 |
| 4 | 复购标准化 | 要反馈、转介绍、固定模板 | 2 家续费+2 家转介绍 | 换渠道补量 |
| 5 | 决定 | 继续 / 修改 / 放弃 | — | — |

**今天做什么**：① 做出 1 个品类（如餐饮）的提示词模板 + 3 条样例；② 列出本地 20 家目标小店名单；③ 给最熟的 3 家免费做 1 条样品并约反馈。
第一笔钱路径：找谁=餐饮小店店主 → 去哪=本地商家群/扫街 → 卖什么=8 条成品文案包 → 报价=199 元首月（代运营 1/10）→ 先收钱再交付。
状态机对齐：HYPOTHESIS → 经样品与报价验证推进 DEMAND_CONFIRMED → MARKET_CONFIRMED → 收首款即 FIRST_PAYMENT。

## 8. 最终判定

🟢 **RECOMMENDED 值得继续做**（78/100，可复算）。第一步：今天做出 3 条品类样品并约 3 家免费试做。
置信度：中（付费意愿与可接受价位仍为 Inference，需 2 周内用真实收款验证）。开放问题：真实可接受月费区间、单店交付耗时、复购率。
