# AI Solution Patterns — 解决方案与 MVP

本文件定义解决方案 Level 1-5、可落地方案清单、技术栈要求、MVP 原则与降级规则。用于 AI Solution Design，以及用户反馈"方案太复杂"时的自动降级。

## 1. 解决方案分级

**只有完成问题分析后才能生成解决方案**（问题 → 证据 → 用户 → 付费 → 竞争，见 `problem-framework.md` / `market-research.md`）。

| Level | 形态 | 适用 | 投入 | 例子 |
|---|---|---|---|---|
| 1 | 人工 + AI | 验证期、第一单 | 最低（几小时~几天） | 手动复制粘贴、AI 生成初稿人工改、每单人工交付 |
| 2 | 半自动化 | 已有 1-3 个付费用户后 | 低 | AI 出初稿 + 人确认；脚本半自动生成 |
| 3 | 自动化工作流 | 交付稳定、需求重复 | 中 | 固定流程脚本化，人工只做质检 |
| 4 | 小工具 | 有明确高频重复任务 | 中 | 单功能脚本 / 简单网页 / 本地小工具 |
| 5 | SaaS / 产品 | 有规模与留存证据后 | 高 | 多用户在线产品、Agent 服务 |

**核心原则**：
- 【先卖结果，再产品化】。
- **先验证，再决定是否开发**：没有付费证据前，不进入开发决策（先完成 Problem / Solution / Payment 三类证据，见 `market-research.md` §三类搜索）。
- 没有真实用户之前，**禁止优先开发复杂 SaaS / Agent**。
- 若"一个人 + AI + 简单工具"即可完成第一次交付，**不默认建议开发完整产品**。
- 必须先尝试：人工 + AI → 真实交付 → 收费 → 复盘。
- 给每个方案指明"当前应该停在哪一级"，不要一次跨级。

## 2. 可落地方案清单（每项必须逐条回答）

- 用户是谁？
- 问题是什么？
- 用户真正想要什么结果？
- 我提供什么？
- AI 做什么？
- 人工做什么？
- 使用什么 AI（哪个模型/工具，理由）？
- 是否需要 Coding？是否需要 Agent？是否需要 API？是否需要数据库？是否需要部署？
- 技术栈是什么？为什么选择？最大缺点？替代方案？
- 第三方依赖有哪些？
- 成本？（现金成本 + 时间成本）
- 时间？（到第一单要多久）
- 交付方式？收费方式？
- 第一位用户在哪里？第一笔钱怎么获得？
- 若不需要开发，明确写【当前不需要开发】。

## 3. 技术方案要求（涉及代码时必须生产级）

- **异常处理**：捕获并处理所有可预期的失败路径，给出可读错误。
- **输入验证**：校验外部输入（用户输入、API 返回、文件），拒绝非法值。
- **日志**：关键步骤记录结构化日志，便于复盘与排错。
- **超时与重试**：外部调用（API/网络）设置超时与有限次重试（指数退避）。
- **配置管理**：密钥与配置不入库，走环境变量/配置文件，不写死。
- **安全**：防注入、防敏感信息泄漏、最小权限；涉及用户数据遵守合规。
- **禁止伪代码**：给出可运行实现或明确标注"需要实现"。

**必须说明**：技术栈、选择理由、最大缺点、替代方案、第三方依赖、成本、瓶颈。
**若不确定某项技术是否必要**，倾向 Level 更低、依赖更少的方案。

## 4. MVP 原则

第一版必须尽可能小。明确写：
- 【第一版做什么】
- 【第一版不做什么】
- 【验证什么】
- 【什么结果出现后继续】
- 【什么结果出现后放弃】

优先验证"是否有人愿意为结果付钱"，而不是"能不能把产品开发出来"。
**能用人工完成的，就不要写代码**；能用现有工具完成的，就不要自建。

## 5. 降级规则（用户反馈"方案太复杂"时自动触发）

按降序检查并逐级降：
1. 砍掉尚未被付费验证的功能（只保留用户已付钱/已确认要的那一项）。
2. 从 Level 4/5 降回 Level 2/3（自动化 → 半自动 → 人工 + AI）。
3. 把"自建工具"换成"现有工具 + 人工编排"（表格、文档、现有 AI 产品）。
4. 缩小用户范围 / 缩小交付范围 / 缩短交付周期。
5. 若降到 Level 1 仍复杂，说明问题本身可能太宽，回到 Problem Analysis 收窄问题。

降级后重新走一遍"可落地方案清单"，确认是否真的更简单、更快到第一单。

## 6. 典型技术栈（参考，非强制）

- **无代码优先**：现成 AI 工具 + 飞书/Excel/表单 + 人工。适用于 Level 1-2。
- **轻脚本**：Python + 官方 SDK，处理文本/表格/批量任务。适用于 Level 2-3。
- **简单前端**：单页 HTML/低代码，用于交付展示或小工具。适用于 Level 3-4。
- **完整产品**：前端 + 后端 + 数据库 + 部署，仅在 Level 5 且有留存证据时。

选择依据始终是"最快验证付费"，不是"技术越先进越好"。
