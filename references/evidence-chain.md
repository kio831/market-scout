# Evidence Chain — 证据链机制（P0）

本文件定义市场侦察中"如何从原始证据得出可信结论"的唯一方法。每个重要市场结论都必须走证据链，禁止跳级。

## 1. 五段式链条

```
原始证据 (Raw Evidence)
   ↓
观察 (Observation)      —— 证据本身表明了什么，不做延伸
   ↓
推断 (Inference)        —— 基于观察与常识的合理延伸，明确标注"这是推断"
   ↓
假设 (Hypothesis)       —— 需要进一步证据验证的猜想，明确标注"这是假设"
   ↓
验证 (Validation)       —— 通过搜索/访谈/测试证明或证伪假设
```

**铁律**：禁止 `原始证据 → 直接得出强商业结论`。
任何一步缺少证据支撑，就必须停留在当前层级并标注不确定性，不得继续向上推。

## 2. 每份证据必须标注的 7 项属性

| 属性 | 含义 | 示例 |
|---|---|---|
| Evidence | 证据原文/内容（尽量引用，不转述变形） | "我每周花 3 小时清理 CSV" |
| Source | 来源（链接/截图/访谈/观察记录） | 某论坛帖子 URL |
| Evidence Type | 证据类型（见 §3） | 直接引用 |
| Confidence | 置信度（高/中/低，见 §4） | 高（一手原文） |
| What this evidence proves | 该证据**能**证明什么（收窄到字面） | 至少存在 1 个用户每周花约 3 小时处理 CSV |
| What this evidence does NOT prove | 该证据**不能**证明什么（防过度解读） | 不能证明"大量企业用户都有此痛点"，不能证明"愿意付费" |
| Date | 采集日期 | YYYY-MM-DD |

## 3. 证据类型

| 类型 | 说明 | 可信度基线 |
|---|---|---|
| 直接引用 | 用户原文/评论原文/帖子原文 | 高（若来源真实） |
| 截图/图片 | 界面、成交、价格、对话截图 | 高（需来源可溯） |
| 搜索命中 | 搜索到多条同类表述/页面 | 中（需看内容本身） |
| 官方页面 | 产品/服务/价格/案例官网 | 高（陈述的是其自身事实） |
| 现实观察 | 自己或用户观察到的真实场景 | 中-高（注明观察者与场景） |
| 访谈记录 | 与潜在用户的一对一交流 | 高（注明访谈对象与时间） |
| 推断 | 基于观察的合理延伸，无直接证据 | 低（必须标注"推断"） |
| 假设 | 模型/用户猜测，无证据支撑 | 极低（必须标注"假设"，且只能作为待验证项） |

## 4. 置信度口径

- **高**：一手来源、可追溯、可复核（原文/截图/官方页面/一手访谈）。
- **中**：二手或聚合来源、来源清晰但无法逐条复核（搜索摘要、媒体报道转述）。
- **低**：来源不明、仅靠模型记忆、无法核实。
- **无来源**：一律视为假设（C 级），禁止当作事实。

## 5. 防跳级示例（必须遵守）

**原始证据**：某个用户说"我每周花 3 小时清理 CSV"。

- ✅ **事实（Observation）**：存在至少一个用户每周花大量时间处理 CSV。
- ✅ **推断（Inference）**：CSV 处理可能存在重复劳动。（明确标注"推断"）
- ✅ **假设（Hypothesis）**：可能存在一批类似用户愿意为自动化解决方案付费。（明确标注"假设"，未验证）
- ❌ **禁止直接写**："市场存在大量企业用户，并且愿意付费。"（跳过了推断、假设与验证，且把假设当成了事实）

**正确写法**：
```
【事实】有 1 个用户称每周花 3 小时清理 CSV（来源：论坛帖，置信度：高）。
【推断】CSV 处理存在重复劳动（推断）。
【假设】可能有类似用户愿意为自动化付费（假设，待验证）。
【证据不足】尚未验证"付费意愿"与"用户规模"，不得据此判定强商业机会。
```

## 6. 证据不足的处理

- 证据不足时，明确写【证据不足】。
- **不得为了凑完整报告而补充模型猜测**。宁可报告"该环节无证据"，也不编造"市场很大""用户很多"。
- 【证据不足】后面必须跟"缺什么证据、去哪补"（指向三类搜索中的对应一类）。

## 7. 证据链在流程中的位置

1. 侦察阶段：收集原始证据 → 每条填 `templates/evidence-card.md`。
2. Problem Card：把证据链（观察/推断/假设）写进"证据链摘要"字段。
3. 评分阶段：每个分数必须引用对应证据（见 `problem-framework.md` §评分绑定证据）。
4. 报告阶段：Top 机会必须附"证据链 + 证据属性表"。
5. 状态机：证据链决定状态是否可推进（见 `opportunity-state-machine.md`）。
