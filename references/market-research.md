# Market Research — 市场侦察与反向分析（v1.1）

本文件定义三类搜索（Problem / Solution / Payment）、侦察来源、视频/内容反向市场分析、评论区需求挖掘、竞争与付费分析、7 天验证模式、30 天侦察模式、Deep Research 与"避免研究上瘾"。用于 Market Scan / Video Reverse Engineering / Comment Demand Analysis / Competitor Research / Deep Market Research。

## 0. 三类搜索（P0 核心）

任何需要判断市场机会的问题，都优先进行三类搜索。**不要只搜"AI 能做什么"。**

```
Problem Evidence（有人遇到这个问题？）
+ Solution Evidence（他们现在怎么解决？）
+ Payment Evidence（有没有人为类似结果付钱？）
= 商业验证基础
```

### 0.1 Problem Search — 证明"真实用户是否遇到这个问题"
- **目标**：找到真实抱怨、求助、重复劳动、时间浪费、错误与效率问题。
- **重点搜索**：用户抱怨 / "有没有工具" / "怎么批量" / "太麻烦" / "每天都要" / "有人能帮我吗" / "求推荐" / "怎么解决" / 重复劳动 / 时间浪费 / 人工成本 / 错误 / 效率问题。
- **产出**：Problem Evidence（每条按 `templates/evidence-card.md` 记录）。

### 0.2 Solution Search — 证明"用户现在如何解决"
- **目标**：弄清用户不用你的方案时是怎么解决的。
- **重点搜索**：软件 / SaaS / 服务商 / 外包 / Freelancer / Agency / 人工服务 / Excel、脚本、自动化方案 / 免费解决方案 / 替代方案。
- **必须回答**："用户现在不用我的方案时，是怎么解决的？"
- **产出**：Solution Evidence（现状 + 为什么不满意 + 缺口）。

### 0.3 Payment Search — 证明"是否已有真实付费行为"
- **目标**：找到"市场上有没有人为类似结果付钱"，而不是"理论上有没有人愿意付钱"。
- **重点搜索**：pricing / price / service / freelancer / outsourcing / quote / cost / agency / paid service / marketplace / 购买行为 / 服务报价 / SaaS 价格。
- **优先寻找**：在售服务、成交案例、公开报价、外包需求、询价行为。
- **产出**：Payment Evidence（价格锚 + 付费行为）。

**纪律**：
- 只有 Problem Evidence、没有 Payment Evidence → 最多判"潜在机会（B）"，**不得判为强商业机会**。
- 每条关键结论都要落到可引用的来源（链接/原文），不凭记忆。
- 搜索不到 ≠ 不存在，只能说"未找到公开证据"（标 C / 【证据不足】）。
- 运行环境无搜索能力 → 声明"【当前无法进行实时市场验证，以下属于假设分析】"，所有结论标 C。

## 1. 侦察来源清单

### 互联网侦察
- **短视频/视频平台**：抖音、视频号、B 站（内容 + 评论区 + 相关推荐）。
- **图文社区**：小红书、知乎（搜"怎么""有没有""太麻烦"）。
- **海外社区**：Reddit（r/smallbusiness、r/productivity、各 niche sub）、Quora。
- **开发者/产品社区**：GitHub Issues、V2EX、垂直论坛/贴吧/群。
- **产品评论**：App Store / 应用市场评论、SaaS 评测站（G2、Product Hunt 等）。
- **电商评价**：淘宝/京东/拼多多/亚马逊（差评含真实抱怨）。
- **招聘信息**：BOSS 直聘/智联/拉勾（反复招什么岗 = 有什么重复劳动外包）。
- **外包需求**：猪八戒、一品威客、Fiverr、Upwork（别人在花什么钱买什么结果）。
- **已存在的付费服务**：淘宝/闲鱼在售服务、知识付费、代做店铺（直接证明"有人为此付钱"）。

### 现实观察
学校、宿舍、公司/实习、商店、小微企业、个体商户、朋友/同学、日常办事流程、重复劳动、信息获取、文件处理、数据处理、沟通流程。
支持 `观察 → 记录 → 搜索 → 对比 → 验证`。

## 2. 视频 / 内容反向市场分析（Video Market Reverse Engineering）

当用户提供视频、文章、帖子、截图、标题或文字稿时，**不只总结内容**，按 13 问反向拆解：

1. 内容讲了什么？
2. AI 实际完成了什么？
3. 产生了什么结果？
4. 谁需要这个结果？
5. 原来如何完成？
6. 原来需要多少时间 / 技能 / 成本？
7. AI 改变了什么？
8. 哪些人不会使用这种能力？
9. 哪些人可能愿意付钱？
10. 是否已有类似服务 / 产品？
11. 当前价格和竞争情况如何？
12. 能否转化为个人服务、自动化、小工具或产品？
13. 一个人能否完成？

核心：**从 AI 能力反推真实需求，而不是从 AI 热点制造项目。**
输出格式参考 `templates/opportunity-card.md` 与 `examples/video-analysis.md`。

## 3. 评论区需求挖掘（Comment Demand Analysis）

从评论/回复中识别并聚类信号：
- **求助**："怎么解决""有没有人会""求教程"。
- **抱怨**："太麻烦""太坑""老出错"。
- **需求**："要是能 XX 就好了""能不能做成 XX"。
- **询价**："多少钱""哪里能买""求链接"。
- **共鸣**："我也遇到""经常发生"。
- **已付费行为**："我花钱找人做的""买过 XX 服务"。

**价值分级**：
- **高价值**（付费信号强）："多少钱？""哪里可以买？""有没有人帮我做？""我愿意付钱。"
- **中价值**（需求信号）："我也遇到。""经常发生。""太麻烦。"
- **低价值**：单纯吐槽。

**重复需求信号**：多个用户反复提到同一问题 → 标记为【重复需求信号】。
**重要**：评论数量 ≠ 付费需求。热度高但没人愿意付钱，依然是低付费证据。评论区挖掘出的每条付费信号，必须用 Payment Search 复核（是否有在售服务/价格/成交）。

## 4. 竞争与付费分析（Competitor Research）

对每个值得研究的问题检查：
- 是否已有工具？是否已有 SaaS？是否已有人工服务？是否有免费方案？
- 用户为什么不用？（贵？不会用？不好用？不知道？）
- 当前价格？竞争者优势？最大缺点？
- 个人是否还有切入空间？（价格锚点、细分人群、更简单的交付、本地化、更贴身的服务）

同时回答：**用户真正购买的是什么？** 不是"买 AI"，而是购买：结果、时间、效率、成本降低、任务完成、信息、质量。
**无付费证据必须明确指出**，不能因为"看起来有需求"就当成能赚钱。

## 5. 三种工作模式（Quick / Research / Execution）

### Quick Mode
用于用户随手输入一个问题（例如"学校打印店经常有人让老板帮忙改 PDF，这有没有机会？"）。
**不要立即生成几十页报告。** 快速输出（`templates/quick-scan.md`）：
- 发现的问题 / 可能用户 / 当前证据 / 证据等级 / 为什么值得或不值得继续 / 最大的不确定性 / 下一步只做一件事。
目标：快速判断"值不值得继续研究"。

### Research Mode
仅当用户明确要求深挖 / 市场研究 / 找竞争 / 找类似需求 / 分析评论区 / 全面验证时进入。
完整走：Problem → Demand → Payment → Competition → AI Leverage → Solution → MVP → First Customer → First Payment → Risk → Decision，输出 Market Scan（`templates/market-report.md`）。

### Execution Mode
当用户说"我准备做 / 我想试一下 / 帮我拿第一单 / 开始执行 / 这个可以做"：
**不要继续无止境研究。** 直接进入执行清单（见 `references/payment-validation.md` §第一笔钱）：
1. 找谁 → 2. 去哪里找 → 3. 提供什么结果 → 4. 怎么展示 Demo → 5. 怎么报价 → 6. 怎么交付 → 7. 怎么收钱 → 8. 今天做什么 → 9. 验证成功标准 → 10. 如果失败下一步怎么办。

**核心原则：研究不是终点，验证才是终点。**

## 6. 7 天验证模式

适合快速验证的问题，逐日执行；**不适合 7 天的项目必须调整，不得机械套用**：

| Day | 动作 |
|---|---|
| 1 | 确认问题与证据（Problem Card + 三类搜索） |
| 2 | 研究现有解决方案（Solution/Payment Search） |
| 3 | 制作最小样品（一份真实交付物） |
| 4 | 寻找潜在用户（从最可能的人群切入） |
| 5 | 低成本测试交付（免费/象征性收费换反馈） |
| 6 | 收集反馈（复购意愿、付费意愿、改进点） |
| 7 | 尝试收费 / 判断放弃 |

## 7. 30 天市场侦察模式（无明确项目时）

| 周 | 动作 |
|---|---|
| W1 | 每天发现 3-5 个问题，只记录不开发 |
| W2 | 筛选 5 个问题（评分粗排） |
| W3 | 研究证据、竞争、价格、付费行为（三类搜索） |
| W4 | 选择 1-2 个最简单的问题，用人工 + AI 实际验证 |

目标不是找到"完美项目"，而是获得第一个真实结果。

## 8. Deep Market Research（继续深挖）

在已有初版结论上做深挖：
1. 补证据：就"最大不确定性"和"缺少的证据"专项搜索（价格、竞品、成交、用户原话）。
2. 补人群：用 Demand Expansion 扩用户画像与付费池。
3. 补竞争：对 Top 竞品逐一拆解（价格/卖点/差评/付费墙）。
4. 补验证：把 B→A 或 C→B 的路径具体化（要找谁、看哪里、问什么）。
5. 输出更新版 Market Scan，标注相对上一版新增/修正的结论。

**注意**：深挖前先检查 Opportunity 状态机（`opportunity-state-machine.md`）——若当前瓶颈是"缺付费证据"，深挖方向应是 Payment Search + 真实用户报价，而不是继续堆 Problem Evidence。

## 9. 避免研究上瘾

当以下全部成立时：
- 有真实问题 ✅
- 有重复需求 ✅
- 有类似服务收费 ✅
- AI 存在明显杠杆 ✅
- 用户可触达 ✅
- 可以低成本完成 MVP ✅

则输出【研究阶段完成】，下一步是【开始真实用户验证】。**不要**为了"更完美"继续搜索、比较、找新机会。
