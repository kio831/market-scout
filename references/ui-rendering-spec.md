# UI Rendering Spec — 输出渲染与视觉规范（v2.0.0 新增，文档型 Skill 的 Design System）

Market Scout 是纯 Markdown 文档型 Agent Skill，没有独立前端。界面就是 Agent 输出的 Markdown 报告与卡片。本文件定义统一的输出渲染规范，让所有阶段卡、报告、状态提示在任何支持 Markdown 的客户端（桌面移动）上都呈现专业、一致、可读的视觉。所有 v2 模板与运行时输出必须遵守本规范；运行时健壮性（超时降级）见 pipeline-and-runtime.md。

## 1. 设计原则

1. 结论先行：用户 10 秒内必须看到在分析什么到得到了什么到下一步做什么。2. 信号一致：同一含义永远用同一视觉符号（信号灯分数条状态标签）不随意换。3. 证据可溯：每个分数结论旁可一眼看到证据或无直接证据标注。4. 克制不堆砌：不用大段 emoji 不用花哨配色信息密度优先于装饰。5. 移动优先：先保证手机竖屏可读再利用桌面宽屏做对比表。

## 2. 字体与标题层级

H1 每份报告卡片唯一主标题含产品名与阶段。H2 大段落（阶段模块）。H3 子模块小节。H4 字段组标题（尽量少用）。正文 15-25 字一行感关键术语加粗。行内代码字段名状态代码 ID 路径。一份报告 H1 只出现一次 H2 不超过 12 个超长报告用目录锚点。关键数字结论行动动词用加粗不要整段加粗。

## 3. 间距与分隔

段落之间空一行 H2/H3 上方空两行营造呼吸感。大阶段之间用水平分隔线卡片内部小字段用表格或字段内容不用分隔线。列表项之间不空行嵌套列表缩进 2 空格。

## 4. 卡片与容器

### 4.1 结论带（每份输出顶部必有）
引用块模拟 Banner 信号灯加核心数据加 ID 一行第二行一句话结论。三档结论固定：绿 GO 黄 VALIDATE_FIRST 红 NO_GO（中文加英文代码双语）。

### 4.2 阶段进度条（五阶段输出必有）
FIND 已完成到 VALIDATE 已完成到 EVALUATE 已完成到 BLUEPRINT 进行中到 MONETIZE 待开始。状态符号：已完成进行中待开始有降级或证据不足。让用户一眼看到 AI 正在分析什么进行到哪一步。

### 4.3 数据卡（关键指标）
用三列表格承载 3-6 个关键指标桌面横向移动端自动换行。

### 4.4 证据卡（沿用 v1.1）
每条重要证据独立成块 7 项属性齐全。

## 5. 评分可视化

### 5.1 分数条（统一 10 格禁止换样式）
实心等于得分空心等于剩余维度名左对齐占固定宽度分数右对齐。0-10 分加权综合分用 0-100 数字加百分条（20 格每格 5 分）。

### 5.2 评分表（每分必带四要素）
维度分理由证据或无直接证据不确定性。桌面用此表移动端（窄屏）改为纵向维度分减理由（证据）键值列表保证不横向溢出。

### 5.3 计算式（可复算）
综合分必须附计算式用 text 代码块。

## 6. 行动按钮与下一步

行动建议用统一格式模拟按钮。行动动词开头（给做找发约）可量化今天能做。相关模板方法用 Markdown 链接标注 emoji 类型（清单实验报告风险）。禁止继续研究深入分析这类无动作的建议。

## 7. 四种状态（Loading / Empty / Error / Success）

所有运行时输出必须明确标注当前状态让用户知道 AI 正在做什么出了什么问题。

### 7.1 Loading（分析进行中）
标注当前阶段正在做的具体动作预计步骤不假装已完成。

### 7.2 Empty（无证据空结果）
明确说没找到什么因此怎么降级处理去哪补禁止用模型记忆补成事实。

### 7.3 Error（调用失败降级）
写明失败原因已执行的重试降级对结论的影响恢复方式不静默失败。

### 7.4 Success（验证通过阶段完成）
给出本阶段关键产出加明确下一步阶段产出落卡（结构化字段齐全）支持断点续跑。

## 8. 长报告阅读体验

顶部必有目录（锚点链接到各 H2）长报告（超过 5 屏）必须有。每阶段开头重复一次阶段进度条让用户随时知道位置。关键结论在每阶段末尾用引用块小结。报告末尾必有行动路线（今天本周 2-4 周）加最终判定。证据原文长引用用引用块不超过 3 行超长证据折叠为见 Evidence Card。

## 9. 移动端优先

任何表格列数不超过 6 超过则拆成多个小表或改纵向键值列表。宽表（超过 4 列）在输出时附一句窄屏查看以下为纵向版并给出字段内容列表。分数条进度条用纯文本字符不依赖图片任何客户端都能渲染。一行不超过约 40 个中文字符的信息密度长句拆短句。按钮链接单独成行不挤在段落里。

## 10. 桌面端信息密度

桌面端优先用对比表（多列）并排指标卡充分利用宽屏。可在报告中用左证据右推断双栏感（用两列表格模拟）。综合评分风险矩阵等可用多列表格一次呈现不用拆段。

## 11. 双语规范

标题固定标签中文（English）如需求验证（Demand Validation）。状态代码字段名 ID 纯英文（GO Demand Strength MS-101）。正文中文为主关键术语首次出现括注英文不逐句翻译。三档结论固定双语：绿值得做 GO 黄建议验证后再做 VALIDATE_FIRST 红不建议做 NO_GO。

## 12. 代码与数据结构区

Schema 契约计算式配置一律用围栏代码块并标注语言 yaml/json/text/python。字段名英文注释中文缩进 2 空格字段对齐。代码块前后空一行行内短字段用反引号。

## 13. 自检清单（输出前必过）

每份 v2 输出交付前逐项核对：顶部有结论带（信号灯加核心分加 ID 加一句话结论）。有阶段进度条用户知道进行到哪一步。评分用统一 10 格分数条综合分附可复算计算式。每分有证据或无直接证据标注无市场很大式空话。有明确的下一步只做一件事行动建议（动词开头可量化）。Loading/Empty/Error/Success 状态有标注无静默失败。表格不超过 6 列窄屏有纵向版或键值列表。长报告有目录每阶段小结末尾行动路线。双语规范一致代码块标注语言。
