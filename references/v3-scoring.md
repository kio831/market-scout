# V3 Opportunity Score — 机会评分（v3.0.0 新增）

> 把 V2 的分析压缩成一个 0-100 的机会评分：7 个维度、每维 0-100、加权合成、
> 计算式可手工复算、每分绑定证据三态。这是 V3 决策的唯一评分口径，产出 `templates/v3-score-card.md`。

## 0. 与 V2 评分的关系（统一口径，不另起炉灶）

- V2 的 8 维问题评分（`problem-framework.md` §4）回答"这个问题值不值得继续研究"，**保留**。
- V2 的 7 维项目评估（`project-evaluation.md` §1-2）回答"作为项目值不值得投入"，**保留**。
- **V3 的 Opportunity Score 是面向用户的最终统一评分**：以 V2 各阶段卡片为输入，按本节 7 维重新组织成用户能直接看懂的 0-100 分。

数据继承规则（沿用 `pipeline-and-runtime.md` §2 单一事实源）：

- Demand 继承 VALIDATE 的需求强度与三层用户，**不重打**。
- Pain / Competition 引用 FIND 的证据与 EVALUATE 的竞争结论。
- Monetization 引用 MONETIZE 的付费证据与定价锚。
- 禁止在前面的阶段给 7 分、到 V3 偷改成 9 分。

## 1. 七个维度（0-100）与权重

| # | 维度 | 权重 | 考问什么 | 高分画像 | 低分画像 |
|---|---|---|---|---|---|
| 1 | Demand 需求强度 | 15% | 需求真不真、频不频、是否在增长 | 多来源重复需求 + 高频 + 主动寻找 + 趋势向上 | 单一个案 / 低频 / 无人主动找 |
| 2 | Pain 痛点强度 | 15% | 不解决的损失有多大 | 直接亏钱/合规风险/每天被折磨，现有方案被公开吐槽 | 只是"有点不方便" |
| 3 | Competition 竞争与切入空间 | 15% | 现有方案能否满足、我有没有空间切入 | 现有方案有明显未满足/明确细分缺口，且切入点守得住 | 现有方案成熟且用户满意，无差异化空间 |
| 4 | Monetization 变现潜力 | 20% | 有没有人付钱、能不能持续收 | 明确在售付费 + 价格锚 + 付费方有拍产权 + 可复购 | 无付费证据 / 无预算 / 无拍产权 |
| 5 | Buildability 开发可行性 | 15% | 最快多久、多少钱能做出最小可售物 | 1-2 周、近零现金成本、L1-L2 可交付 | 多月开发 / 重资金 / 需要团队 |
| 6 | Distribution 获客难度 | 10% | 能不能低成本触达目标用户 | 用户高度聚集、本人可触达、有内容/口碑获客潜力 | 触达不到客户、无获客路径 |
| 7 | AI Advantage AI 优势 | 10% | AI 是否带来决定性成本/速度/门槛优势 | AI 显著降本/提速/降门槛，质量稳定可控 | AI 无杠杆，或质量不可控需大量人工兜底 |

- 权重是默认权重。可按用户约束调整（如用户资金极少 → 调高 Buildability），但必须在报告中写明"改了什么、为什么"，禁止为凑高分事后调权重（沿用 `project-evaluation.md` §1）。
- Monetization 权重最高：个人项目死因多半是"没人付钱"。

## 2. 评分方法（可复算）

### 2.1 每维 = 子信号均分 × 10

每维拆 3-4 个子信号，各打 1-10 分，均分 ×10 = 维度分（0-100）：

| 维度 | 子信号（1-10） |
|---|---|
| Demand | D1 需求真实性（多来源重复证据）｜D2 发生频率｜D3 主动寻找｜D4 增长趋势 |
| Pain | P1 损失量化（钱/时间/风险）｜P2 情绪/后果强度｜P3 对现有方案的不满证据 |
| Competition | C1 现有方案成熟度（反向：越成熟满意越低）｜C2 用户未被满足的程度（抱怨/缺口证据）｜C3 差异化空间｜C4 对手复制难度 |
| Monetization | M1 付费证据（Payment 分档 1-10，`problem-framework.md` §4）｜M2 客单价/预算｜M3 付费方与拍产权｜M4 复购/订阅可能 |
| Buildability | B1 MVP 工作量（越少越高）｜B2 现金成本（越低越高）｜B3 技术/AI 成熟度｜B4 单人可完成 |
| Distribution | D1 渠道可触达｜D2 用户聚集度｜D3 内容/口碑获客潜力｜D4 获客成本（越低越高） |
| AI Advantage | A1 降本幅度｜A2 提速幅度｜A3 质量稳定性｜A4 相对替代方案的 AI 优势 |

### 2.2 合成公式（必须显式列出，禁止只给总分）

```text
Opportunity Score = Σ(维度分 × 权重)，四舍五入到整数
示例：
= 88×0.15 + 91×0.15 + 62×0.15 + 80×0.20 + 94×0.15 + 61×0.10 + 89×0.10
= 13.2 + 13.65 + 9.3 + 16.0 + 14.1 + 6.1 + 8.9
= 81.25 → 81/100
```

输出必须同时给：

1. **维度分表**（分/权重/子信号分/理由/证据徽标）。
2. **计算式**（让用户能复核分数怎么来的）。
3. **20 格百分条**（`ui-rendering-spec.md` §5.1，每格 5 分）。
4. **最强两项与最弱两项**（"这个机会靠什么成立、可能死在哪里"）。

### 2.3 每分四要素（沿用 v1.1）

每个子信号：**分数 + 评分理由 + 对应证据（或【无直接证据】）+ 当前不确定性**。禁止凭主观感觉打分。

### 2.4 证据三态计分规则（配合 v3-evidence.md）

- Unknown 子信号 → 按 0 计，并在表中显式标注"Unknown，按 0 计，本维度被低估，补齐证据后重算"。
- Inference 子信号 → 最高 7/10。
- Evidence 子信号 → 无上限。
- 某维度一半以上子信号为 Unknown → 该维度标"低可信"，决策时降档考虑（`v3-decision.md` §4）。
- 不得为了让总分好看把 Unknown 写成 Inference。

## 3. Competition 维度特殊规则（P0，禁止"竞争低=高分"）

竞争维度的分数 = **切入空间大小**，不是"竞品数量少"：

- ❌ 错误逻辑：没有竞品 → 蓝海 → 高分。没有竞品通常意味着需求未成立，必须回到 VALIDATE 查证（`project-evaluation.md` §3.1）。
- ❌ 错误逻辑：竞品很多 → 红海 → 低分。竞争激烈 + 需求强烈可能是好机会——关键是还有没有切入空间。

**切入空间四问（必答，输出到评分卡）**：

1. 用户有没有真实需求？（引用 VALIDATE 结论）
2. 竞品有没有把问题解决到位？（引用 Solution Search / 竞品差评）
3. 用户是否仍在抱怨？（未满足程度证据：差评/吐槽/求助仍在出现）
4. 有没有可守的差异化切入点？（细分人群/场景/结果交付/价格/本地化/垂直整合，`project-evaluation.md` §3.2）

判分锚点：

| C1-C4 综合画像 | Competition 分 |
|---|---|
| 切入空间四问全部有证据成立，切入点对手短期难复制 | 70-100 |
| 有未满足证据与差异化空间，但需要进一步验证 | 50-69 |
| 有竞争但切入空间证据不足（多为 Inference/Unknown） | 30-49 |
| 现有方案成熟且用户满意，或无任何切入空间证据 | 0-29 |
| **无法给出任何切入空间证据 → 封顶 40** | ≤ 40 |

## 4. 致命红旗（一票否决，复用 project-evaluation §6）

- R1 无真实重复需求（VALIDATE 已判弱/伪需求）。
- R2 不存在任何付费可能（无预算、无拍产权、纯公益预期）。
- R3 AI 无杠杆且纯人工无法持续。
- R4 个人无法触达目标客户且无低成本获客路径。
- R5 竞争被巨头/免费方案碾压且无结构性差异化空间。
- R6 需要重资金/长周期/团队才能做出最小可售物。
- R7 合规/法律/平台规则明确禁止或高度灰产。

触发任一 → Decision=NOT_RECOMMENDED（`v3-decision.md`），无论总分多高。

## 5. 输出

- 使用 `templates/v3-score-card.md`：7 维表 + 子信号 + 计算式 + 百分条 + 最强/最弱 + 切入空间四问 + 红旗检查。
- 低可信维度、Unknown 计分、权重调整必须显式标注。
- 评分是 Decision 的直接输入（`v3-decision.md`）。
